# Project Conventions

## Share the process and source files

Start with a repository and a short README, then update it as the project develops. Do not wait for a finished product. Open a PR after an initial change and describe the intended work; use a Draft PR while it is unfinished. A PR requires a difference between branches.

Upload source code, original materials, build configuration, and running instructions - not only an exported HTML page. Ask AI for the complete source project. A single HTML file is fine if it is the actual source project. Keep passwords, API keys, and reinstallable dependency folders out of Git.

## Name and move repositories

After joining the organization, transfer your existing project or create a new repository there, subject to permissions. Names must start with `project-`, for example `project-physics-map`. A username is not required in the name. If the name is taken, add a word that distinguishes the project.

For renaming, look in **Settings → General → Repository name**. For transferring, use **Settings → General → Danger Zone → Transfer ownership**. You need administrative access to the original repository and permission to create repositories in the organization. Ask AI for the detailed steps; contact **@qftgtr** in a Dashboard Issue if permissions are missing. After a move or rename, check links to demos and GitHub Pages.

The teacher will configure course members' read access to private project repositories. Editing permissions are arranged separately.

## Keep README useful

Include the project's purpose, members' real names and GitHub usernames, current progress, and links to the work. Update members and roles when the team changes. Contribution history shows individual changes; the member list identifies the team.

Keep your project review in **`plan.md` at the repository root**. Use the framework in [Lesson 02](../Tasks/lesson-02.md#task-3-review-your-project-in-planmd).

Write project descriptions, README content, and planning notes in English whenever possible. Use AI to help express your ideas, then check that the text says what you mean. Use your real name for identification.

## Discuss and collaborate

Course-wide questions belong in Dashboard Issues. Questions about a specific project - including your own - belong in that project's Issues. Mention **@qftgtr** when you need the teacher to respond.

Read others' Issues, add relevant experiences, and help when you have an answer or an idea. Browse projects to find similar interests or possible teammates. Star interesting repositories as bookmarks; more Stars usually mean more attention, not a course grade.
